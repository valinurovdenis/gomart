
# Гофермарт (Gomart)

**Гофермарт** — HTTP API накопительной системы лояльности интернет-магазина, реализованное на Go. Сервис позволяет пользователям регистрироваться, добавлять номера заказов, получать бонусные баллы и списывать их при оплате новых покупок.


## Возможности

- Регистрация и аутентификация пользователей.
- Приём номеров заказов и проверка их корректности по алгоритму Луна.
- Хранение истории заказов и отслеживание статусов обработки.
- Получение начислений от внешней системы расчёта баллов лояльности.
- Просмотр текущего баланса и общей суммы списаний.
- Списание баллов в счёт оплаты новых заказов.
- Просмотр истории списаний.

## Начало работы

### Требования

- Go 1.23.2 или новее.
- Запущенный PostgreSQL.
- Доступ к внешнему сервису расчёта начислений (для полноценной обработки заказов).

### Установка

```bash
git clone https://github.com/valinurovdenis/gomart.git
cd gomart
go mod download
```

### Конфигурация

Согласно спецификации сервис принимает настройки через переменные окружения или флаги командной строки:

| Переменная окружения | Флаг | Описание |
| --- | --- | --- |
| `RUN_ADDRESS` | `-a` | Адрес HTTP-сервера |
| `DATABASE_URI` | `-d` | Строка подключения к PostgreSQL |
| `ACCRUAL_SYSTEM_ADDRESS` | `-r` | Адрес внешнего сервиса начислений |

Пример настройки окружения (замените значения на свои):

```bash
export RUN_ADDRESS="localhost:8080"
export DATABASE_URI="postgres://postgres:postgres@localhost:5432/gomart?sslmode=disable"
export ACCRUAL_SYSTEM_ADDRESS="http://localhost:8081"
```

Создайте базу данных `gomart` перед запуском, если она ещё не существует. Убедитесь, что схема БД подготовлена способом, предусмотренным приложением.

### Запуск

В репозитории исходный код приложения размещён в `cmd/` и `internal/app/`. Точную точку входа следует уточнить по файлам в `cmd/`.

Если в `cmd/` находится единственный исполняемый Go-пакет, запустите его командой:

```bash
go run ./cmd/<имя_пакета>
```

Замените `<имя_пакета>` фактическим названием каталога с `main.go`.

## HTTP API

Все пользовательские методы, кроме регистрации и входа, требуют аутентификации.

| Метод | Endpoint | Назначение |
| --- | --- | --- |
| `POST` | `/api/user/register` | Регистрация |
| `POST` | `/api/user/login` | Вход |
| `POST` | `/api/user/orders` | Добавление номера заказа |
| `GET` | `/api/user/orders` | Список заказов и начислений |
| `GET` | `/api/user/balance` | Баланс бонусного счёта |
| `POST` | `/api/user/balance/withdraw` | Списание баллов |
| `GET` | `/api/user/withdrawals` | История списаний |

### Регистрация

```http
POST /api/user/register
Content-Type: application/json

{
  "login": "example_user",
  "password": "strong_password"
}
```

При успешной регистрации пользователь автоматически аутентифицируется.

### Вход

```http
POST /api/user/login
Content-Type: application/json

{
  "login": "example_user",
  "password": "strong_password"
}
```

Сохраните полученные данные аутентификации и передавайте их в последующих запросах в формате, предусмотренном реализацией.

### Добавление заказа

```http
POST /api/user/orders
Content-Type: text/plain

12345678903
```

Номер заказа должен состоять из цифр и проходить проверку алгоритмом Луна. Новый заказ принимается в обработку с кодом `202 Accepted`.

### Получение заказов

```http
GET /api/user/orders
```

Пример ответа:

```json
[
  {
    "number": "9278923470",
    "status": "PROCESSED",
    "accrual": 500,
    "uploaded_at": "2025-01-10T15:15:45+03:00"
  },
  {
    "number": "12345678903",
    "status": "PROCESSING",
    "uploaded_at": "2025-01-10T15:12:01+03:00"
  }
]
```

Статусы заказов:

- `NEW` — заказ зарегистрирован в системе.
- `PROCESSING` — начисление рассчитывается.
- `INVALID` — заказ отклонён системой начислений.
- `PROCESSED` — расчёт завершён.

### Получение баланса

```http
GET /api/user/balance
```

Пример ответа:

```json
{
  "current": 500.5,
  "withdrawn": 42
}
```

`current` — доступные баллы, `withdrawn` — сумма ранее списанных баллов.

### Списание баллов

```http
POST /api/user/balance/withdraw
Content-Type: application/json

{
  "order": "2377225624",
  "sum": 100
}
```

При недостаточном балансе API возвращает `402 Payment Required`.

### История списаний

```http
GET /api/user/withdrawals
```

Пример ответа:

```json
[
  {
    "order": "2377225624",
    "sum": 100,
    "processed_at": "2025-01-10T16:09:57+03:00"
  }
]
```

## Интеграция с системой начислений

Внешний сервис предоставляет метод `GET /api/orders/{number}`. Он возвращает статус расчёта и, если начисление предусмотрено, количество баллов.

Возможные статусы: `REGISTERED`, `PROCESSING`, `INVALID`, `PROCESSED`. При ответе `429 Too Many Requests` внешний сервис может передавать заголовок `Retry-After`.
